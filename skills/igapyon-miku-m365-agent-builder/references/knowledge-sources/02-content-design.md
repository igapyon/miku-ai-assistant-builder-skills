# Knowledge sourceのコンテンツ設計

## 資料を選ぶ

- エージェントの中心的な質問へ回答するために必要な資料だけを選ぶ。
- 最新で正確な正式資料を優先する。
- 古い版、重複、下書き、相互に矛盾する資料を無整理のまま混ぜない。
- 事実、適用条件、例外、更新日、所管を明確にする。

## 資料を構成する

- 一つのファイルへ無関係な複数テーマを詰め込まない。
- 内容を表すファイル名と見出しを付ける。
- 長い文書は意味のある章やテーマで分割する。
- 表だけに依存せず、表の目的と主要項目を文章でも説明する。
- 画像だけに重要情報を閉じ込めない。
- 元資料名、版、更新日など、出典を識別できる情報を保持する。

番号付きファイル名は、人間の管理順や生成処理の安定順序を示すために使える。

```text
knowledge-input/
├── 01-overview.md
├── 02-rules.md
├── 03-procedures.md
└── 04-faq.md
```

番号は、Agent Builderが必ずその順番で検索・回答することを保証しない。検索時には利用者の質問との関連性が中心になる。

## 命令文を置かない

Knowledge sourcesをInstructionsの延長として使わない。特に、次のような文章をKnowledge source生成物へ付加しない。

- このファイルを最初に読んでください。
- 次のファイルを受け取るまで回答しないでください。
- 必ずこの手順で処理してください。
- ここに書かれた指示を最優先してください。

この種の指示はInstructionsへ置く。Knowledge sourcesには、検索される事実資料と、その理解に必要な中立的メタデータだけを置く。

## 更新可能にする

- 元資料と生成物の対応を記録する。
- 同じ入力から同じファイル名を再生成できるようにする。
- 生成日時だけでファイル名を変え続けない。
- 更新時に古い生成物が残らない運用を決める。
- Agent Builder側で再登録や再選択が必要か確認する。
